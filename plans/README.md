## Found by the plan-021 e2e harness (2026-07-06) — worth a look

- **Undo-after-AI-accept data loss** → now **plan 022** (P1). Server undo tree is
  correct; the client pointer can go stale and a single Undo blanks the editor +
  syncs `""` up.
- **Pre-hydration keystrokes dropped** — text typed before the history controller
  hydrates isn't recorded as undo nodes (`recordChange` no-ops while the ref is
  null). Folded into plan 022's scope as a cheap-if-safe secondary fix.
- **Fresh-doc input clobbered by async server seed** — typing in the first ~1s of
  a new document can be overwritten by the seed (harness works around it). UX
  papercut, unplanned.
- **CodeMirror ships only `searchKeymap`** — Home/End and similar are native
  no-ops in the raw/vim lenses; confirm this is intended (it may be, given the
  Vim layer) before treating as a bug.
- **Main checkout `.env.local` has a dead `OPENROUTER_API_KEY`** — it returned 401
  from OpenRouter during the e2e run; the dev *deployment* env key is valid.
  Refresh the local file when convenient (ops, not code).

## Cross-cutting conventions (every plan restates these, summarized here)

- Bun: `bun run typecheck` · `bun run biome` · `bun run test` · `bun run build` · `bun run dev`.
- TS strict + ESM; prefer built-ins/battle-tested libs over custom; UI composes shadcn primitives; dark-only OKLCH tokens.
- Convex is the only persistent write path; single-user scoping via `requireUserId`/`requireOwnedDocument`.
- Editor owns live state — never bind an editor value to a reactive `useQuery` (clobbers cursor).
- Commits: conventional `type: description`, **no AI attribution / Co-Authored-By**, author = user only. Don't push/PR unless asked.
- Where there's a genuine A/B UX fork, ship a **switchable user setting**, don't hard-pick (standing preference). Plans 001/003/004/007/008 each expose such toggles.

## Findings considered and rejected (so they aren't re-audited)

Feature directions intentionally **not** planned — they clash with Recto's single-user, lossless-Markdown, typography-first, "tool disappears" philosophy:

- **Block / drag-handle editor model** (Notion/Craft) — fights canonical Markdown and the Vim lens.
- **Real-time collaboration / presence / comments** — single-user is a load-bearing design choice, not a gap (blueprint §8).
- **Tracked-changes / "Suggesting" mode** — value is collaboration-derived; the undo tree + word diff (001) serve the solo case.
- **Plugin / extensibility platform** — mine plugins for ideas; don't become a platform (blueprint §8 non-goal).
- **Color-picker theming surface** — Bear/Craft win by *curation*; ship a few impeccable themes (already done), resist a config surface.
- **Full-draft AI generation / always-on ghost text** — clashes with "the tool disappears" and the 2025–26 "slop" backlash; 009 is deliberately *augment-not-replace* (reversible transforms, critique, retrieval of the writer's own material).
- **Light theme** — dark-only is locked (D13); recent themes work stays within dark OKLCH.

Sub-decisions rejected inside plans:
- Custom ProseMirror find/replace engine for the rich lens (006) — high cost, redundant with CodeMirror's built-in search; the lossless lens switch lets rich route to raw instead.
- A new Convex column for newsletter subject/preview text (008) — would break "the Markdown string is the source of truth at rest"; stored in YAML frontmatter instead so it round-trips losslessly.
- Turndown for HTML→Markdown (007) — would introduce a second Markdown dialect; the existing unified `rehype-parse → rehype-remark → remark-stringify` pipeline reuses the canonical stringify config.
- "Copy for Substack/Ghost" presets (008) — the existing copy-as-markdown / copy-as-rich-text actions already suffice.
